# 变更管理（Git / 依赖 / ADR，横切规范）

> 本文件是跨栈规则。`stack/backend.md`、`stack/frontend.md`、`stack/database.md` **不再重复**本文件内容，只保留链接指向。

## 1. Git 安全规范

修改代码前，必须查看 `git status`。
保护用户已有的修改。

禁止：

- 重置无关变更
- 覆盖他人代码
- 删除无关文件
- 强制推送
- 改写公共提交历史
- 修改非本人创建的 commit（除非明确要求）

## 2. 依赖变更

新增依赖包前：

1. 检查现有依赖是否已经可以解决该问题
2. 评估包的维护状态
3. 评估安全风险
4. 评估运行时 / 打包体积影响
5. 评估兼容性
6. 评估长期维护成本

不要为了一点点开发便利就引入新依赖。

## 3. 架构决策记录

架构相关决策记录存放路径：`docs/architecture/decisions/`

发生以下变更时，新建或者更新 ADR 文档：

- 架构改动
- 状态归属变更
- API 接口规范
- 数据库架构
- 缓存架构
- 登录鉴权
- 权限体系
- 基础设施
- 重大依赖变更
- 跨模块边界修改

不能悄无声息引入架构层面改动。
