# 测试与校验（横切规范）

> 本文件是跨栈规则。`stack/backend.md`、`stack/frontend.md` **不再重复**本文件内容，只保留链接指向。

## 1. 测试用例是事实依据

不能为了让代码跑通，就弱化测试断言。

如果业务行为需要主动变更：

1. 确认需求确实发生变更
2. 修改业务实现
3. 更新测试用例
4. 说明行为变更原因

不能仅仅因为测试用例跑起来麻烦，就删掉有意义的断言。

## 2. 自动化校验

使用仓库内定义好的脚本命令。新增命令前先查看 package.json。

校验包含：

- 代码格式化校验
- TS 类型检查
- 单元测试
- 集成测试
- 端到端 E2E 测试
- 构建校验
- 数据库校验
- 迁移脚本校验

只有真实执行过命令，才可以宣称校验通过。

## 3. 基于风险等级做校验

校验的严格程度和风险等级匹配。

### 低风险

示例：样式、文案、纯展示组件
一般校验：格式化检查、类型检查、相关测试

### 中风险

示例：React Query、Zustand、API 接口行为、表单、业务逻辑
一般校验：格式化检查、类型检查、单元测试、集成测试、构建校验

### 高风险

示例：登录鉴权、权限、支付、订单、库存、数据库迁移、Redis 锁、并发逻辑
一般校验：格式化检查、类型检查、单元测试、集成测试、E2E 测试、构建校验、迁移脚本校验、安全评审、并发逻辑评审
