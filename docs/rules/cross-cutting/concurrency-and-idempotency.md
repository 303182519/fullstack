# 并发与幂等（横切规范）

> 本文件是跨栈规则。`stack/backend.md`、`stack/frontend.md` **不再重复**本文件内容，只保留链接指向。

## 1. 并发处理

每一处会修改数据的操作，都必须考虑并发场景。
自问：是否会有两个请求同时执行？

需要考虑手段：

- 数据库事务
- 唯一约束
- 原子更新
- 乐观并发
- 悲观锁
- Redis 协同
- 幂等性

不要默认请求都是串行依次执行。

## 2. 幂等性

任何有可能被重试的操作，都必须评估幂等性。
示例场景：

- 创建类操作
- 支付逻辑
- Webhook 回调
- 后台任务
- 调用外部 API

重试操作绝对不能意外产生重复业务效果。

## 3. 后端落地手段

会修改数据状态的操作，必须考虑并发执行场景。
处理手段参考：

- 数据库事务
- 数据库原子操作
- 数据库唯一约束
- 乐观并发控制
- 锁机制
- 幂等性设计

存在重试可能性的操作，必须明确设计幂等语义。
重点场景：

- 资源创建类接口
- 支付相关操作
- Webhook 回调
- 后台任务
- 第三方外部系统对接

## 4. 前端 Mutation 需考虑的项

以下项属于跨栈规则，在前端发起修改请求时同样必须考虑：

- 重复提交
- 重试策略
- 幂等性
- 并发修改
- 鉴权失败

（前端特有的乐观更新、回滚、缓存失效、过期状态见 `stack/frontend.md`。）
